# 커머스 페이지 패턴

상품 목록(PLP)·상품 상세(PDP)·장바구니·주문서 화면의 구조를 정할 때 읽는다. 섹션 이름은
`${CLAUDE_PLUGIN_ROOT}/references/sections.md` 의 id 만 쓴다.

커머스 화면의 일은 "이 상품이 맞는지 확신시키고, 결제까지 막힘없이 보내는 것"이다. 예쁜 화면보다 가격·배송·교환 정보가
제자리에 있는 화면이 더 판다. 구매자는 가격 위계, 이미지 비율, 배송비가 조금만 어긋나도 신뢰를 잃는다.

## 1. 하위 유형 (Subtypes)

### 1.1 계열

| 계열 | 목적 | 대표 예시 성격 | 기본 섹션 순서 요약 |
|---|---|---|---|
| 큐레이션형 (editorial) | 브랜드·취향을 고르게 한다. 상품 수가 적거나 고른 상품 | 29CM 같은 에디토리얼 편집숍, 브랜드 자사몰 | hero-media(기획전) → text-block(이야기) → product-grid(3–4열, 큰 이미지) → media-text → product-grid |
| 카탈로그형 (catalog) | 많은 상품에서 빨리 찾게 한다. 가격·조건 비교 | 종합 오픈마켓, 대형 패션 플랫폼 | category-nav → sort-bar + filter-sidebar → product-grid(4–5열, 밀도 높음) → pagination |

### 1.2 하위 페이지

| 하위 페이지 | 목적 | 대표 예시 성격 | 기본 섹션 순서 요약 |
|---|---|---|---|
| PLP (상품 목록) | 후보를 좁힌다 | 카테고리·검색 결과·기획전 | category-nav → sort-bar → filter-sidebar → product-grid → pagination |
| PDP (상품 상세) | 확신시키고 담게 한다 | 상품 페이지 | pdp-gallery + pdp-buybox → pdp-tabs → detail-images → review-summary → review-list → 문의 → 배송·교환 → 추천 product-grid |
| 장바구니 (cart) | 고른 것 정리, 금액 확인 | 장바구니 | 전체선택·선택삭제 → free-shipping-bar → cart-line → order-summary |
| 주문서 (checkout) | 막힘없이 결제 | 주문/결제 | checkout-step(배송지 → 할인 → 결제수단) → agree-all → order-summary + 결제 버튼 |

## 2. 섹션 순서와 이유

### 2.0 상품 카드 (product-card) 해부

카드는 커머스의 기본 단위라 모든 목록에서 같은 규칙을 쓴다. 위에서 아래로:

1. 이미지 — 사이트 전체에서 비율 하나로 통일한다. 패션·뷰티는 3:4, 리빙·식품·전자는 1:1 이 흔하다. 오른쪽 위에 찜(하트)
   아이콘, 터치 영역은 44px. 품절이면 이미지 위에 반투명 "품절" 덮개.
2. 브랜드 — 12–13px, 굵게 또는 회색. 큐레이션형은 브랜드가 먼저 읽혀야 하므로 굵게.
3. 상품명 — 13–14px, 최대 2줄 말줄임. 줄 수를 고정해야 카드 아래 가격 줄이 가로로 맞는다.
4. 가격 블록 — `30%` 할인율(빨강 계열, 굵게) + `69,000원` 판매가(굵게, 15–16px)를 한 줄에, 정가 `99,000원` 은 취소선 +
   12–13px 회색으로 그 위나 옆에. 판매가가 가장 크고 진해야 한다. 할인율은 정가가 있을 때만 쓴다.
5. 배지 — 쿠폰·무료배송·오늘출발 같은 혜택 1–2개. 3개를 넘으면 아무것도 안 읽힌다.
6. 리뷰 — 별점 평균 + 리뷰 수(`4.8 (1,203)` 형식, 12px). 리뷰가 없으면 줄째 뺀다.

### 2.1 PLP (상품 목록)

1. `nav` — 로고, 검색(넓게, 최근·인기 검색어), 카테고리, 장바구니(담긴 수 배지), 마이페이지.
2. `category-nav` — 브레드크럼 + 현재 카테고리 제목 + 하위 카테고리 칩(가로 스크롤). 상위로 돌아가는 길과 옆으로 가는 길을 같이 준다.
3. `sort-bar` — 왼쪽 "총 1,284개", 오른쪽 정렬(추천순·신상품순·판매순·낮은 가격순·높은 가격순·리뷰 많은순)과 보기 전환(2열·4열).
4. `filter-sidebar` — 데스크톱은 왼쪽 220–260px: 카테고리 → 가격 → 브랜드 → 사이즈·색상 → 혜택(무료배송·할인) 순. 항목마다
   접기, 선택 수 표시. 적용된 필터는 그리드 위에 칩으로 + "초기화". 모바일은 [필터] 버튼 → `bottom-sheet` 전체 높이,
   하단에 [N개 상품 보기] 버튼(결과 수를 미리 보여준다).
5. `product-grid` — 데스크톱 4열(큐레이션형은 3열, 카탈로그형은 5열까지), 간격 16–24px. 모바일 2열, 간격 8–12px, 좌우 여백 16px.
6. `pagination` 또는 "더보기"(무한 스크롤) — 무한 스크롤이면 상세에서 돌아올 때 위치를 복원한다. 복원이 안 되면 구매자는
   비교하던 상품을 다시 찾느라 떠난다.

왜 이 순서인가: "어디에 있나(category) → 몇 개 있나·어떻게 늘어서 있나(sort) → 좁히기(filter) → 고르기(grid)". 필터를
그리드 왼쪽에 두는 건 좁히면서 결과를 동시에 보게 하려는 것이다.

### 2.2 PDP (상품 상세)

1. `pdp-gallery` — 데스크톱 왼쪽 55–60%: 큰 이미지 + 썸네일 세로 열(또는 이미지를 세로로 늘어놓는 방식). 확대 보기. 모바일은
   전폭 스와이프 + "1/8" 카운터.
2. `pdp-buybox` — 데스크톱 오른쪽 400–480px, 스크롤해도 따라오는 sticky. 순서:
   브랜드(링크) → 상품명(20–24px) → 별점·리뷰 수(누르면 리뷰 탭으로) → 가격 블록(2.0 규칙, 판매가 24–28px) →
   혜택(쿠폰 받기 버튼, 카드 할인, 적립금) → 배송(배송비, 무료배송 기준, 도착 예정일) → 옵션 선택(드롭다운 또는 칩) →
   선택한 옵션 줄(옵션명 · 수량 스테퍼 · 금액 · 삭제) → 총 상품 금액 → [장바구니] [바로 구매] + 찜.
   가격과 배송비가 버튼 바로 위에 있어야 마지막 순간의 "얼마지?"에 답한다.
3. `pdp-tabs` — 상품정보 / 리뷰(N) / 문의(N) / 배송·교환·반품. 상단에 sticky, 누르면 해당 위치로 스크롤(앵커).
   탭이 페이지를 바꾸지 않고 긴 한 페이지의 목차 역할을 하게 한다.
4. `text-block` 핵심 정보 — 소재, 사이즈표(표), 세탁·보관, 구성품. `detail-images` 앞에 텍스트로 둔다(5장).
5. `detail-images` — 판매자가 만든 세로로 긴 상세 이미지. 처음에는 1,200–1,600px 높이까지만 보여주고 "상품정보 더보기"로 펼친다.
6. `review-summary` — 평균 별점, 별점 분포 막대, 옵션별 만족도(사이즈: 작아요·잘 맞아요·커요), 포토 리뷰 썸네일 줄.
7. `review-list` — 필터(포토만·별점·옵션·내 체형과 비슷한), 정렬(최신·추천). 리뷰 한 건: 별점 · 닉네임(일부 가림) · 날짜 →
   구매 옵션 · 체형 정보(키·몸무게·평소 사이즈) → 본문 → 사진 → 도움돼요 N.
8. 상품 문의(`board-list` 변형) — 문의 목록(답변 상태 배지, 비밀글 잠금) + [문의하기].
9. 배송·교환·반품(`text-block`, 표 포함) — 배송비·기간, 교환·반품 기간과 비용, 불가 사유, 판매자 정보. 표로.
10. 추천 `product-grid` — "함께 본 상품", "같은 브랜드". 4–8개, 한 줄 가로 스크롤.

모바일은 2번 `pdp-buybox` 의 옵션·버튼을 화면에 펼치지 않고 하단 `sticky-buy-bar`(찜 + [구매하기], 56–64px + safe-area)로
옮긴다. [구매하기]를 누르면 `option-sheet`(바텀시트)가 올라와 옵션 선택 → 수량 → 총액 → [장바구니] [바로 구매]를 보여준다.

### 2.3 장바구니 (cart)

1. `page-header` "장바구니 (3)" — 판매자 배송이 섞이는 마켓플레이스면 탭(일반 배송·오늘출발)을 둔다.
2. 선택 줄(`cart-line` 묶음 머리) — [v] 전체선택 (2/3) · 선택삭제 · 품절 상품 삭제.
3. `free-shipping-bar` — "12,000원 더 담으면 무료배송" + 진행 바. 무료배송 기준이 있을 때만.
4. `cart-line` 반복 — 체크박스 → 썸네일(카드와 같은 비율) → 브랜드·상품명 → 옵션(변경 버튼) → 수량 스테퍼 → 금액(할인 전
   취소선 + 할인 후) → 삭제(X). 판매자·배송 묶음별로 그룹 제목과 배송비를 단다.
5. `order-summary` — 데스크톱은 오른쪽 sticky 340–380px: 상품 금액 → 할인 금액(-, 빨강) → 배송비 → 결제 예정 금액(가장 크게)
   → [N개 상품 구매하기]. 모바일은 하단 고정 바에 결제 예정 금액 + 버튼.
6. 추천 `product-grid` — 장바구니가 비었거나 무료배송까지 남은 금액이 있을 때.

### 2.4 주문서 (checkout)

국내 주문서는 단계를 페이지로 나누지 않고 한 페이지에 `checkout-step` 블록을 쌓는 방식이 흔하다. 결제 예정 금액이 계속
보여서 할인·배송비 변화를 바로 확인할 수 있기 때문이다.

1. 주문자 정보 — 회원이면 접힌 요약 한 줄(이름·연락처) + 변경.
2. 배송지 — 기본 배송지 카드(받는 분·연락처·주소) + [배송지 변경] → 배송지 목록 시트. 새 주소는 우편번호 찾기 → 기본 주소 →
   상세 주소. 배송 메모는 선택형(문 앞에 놓아 주세요·경비실에 맡겨 주세요·배송 전 연락 주세요·직접 입력).
3. 주문 상품 — 접힌 요약("○○ 외 2건") + 펼치기.
4. 할인·적립 — 쿠폰 선택(적용 가능 N장, 최대 할인 자동 적용 버튼), 적립금·포인트 사용(보유액 표시, [전액 사용]).
5. 결제수단 — 2–3열 그리드 버튼: 신용·체크카드 / 간편결제(카카오페이·네이버페이·토스페이 등, 각 사 로고 가이드 준수) /
   무통장입금(가상계좌) / 휴대폰 결제. 카드를 고르면 카드사·할부 선택이 아래에 펼쳐진다. 지난번 수단을 기본 선택해 둔다.
6. `agree-all` — "주문 내용을 확인했고 결제에 동의해요"(전체 동의) + 개별 항목(개인정보 제3자 제공 등) 펼침.
7. `order-summary` + 결제 버튼 — 데스크톱 오른쪽 sticky, 모바일 하단 고정. 버튼 라벨에 금액을 넣는다("58,000원 결제하기").

## 3. 첫 화면 계약 (Above the fold)

### 데스크톱 1440×900

- PLP: 카테고리 제목·하위 칩, `sort-bar`, 필터 첫 2–3그룹, 상품 카드 2줄(4열이면 8개)이 가격 줄까지 보인다. 기획전 배너가
  있으면 높이 240–320px 이하로 둬서 상품이 첫 화면에 남게 한다.
- PDP: 큰 이미지 + `pdp-buybox` 의 상품명·가격·옵션·[바로 구매]가 스크롤 없이 보인다. 옵션이 많아 버튼이 밀려나면
  옵션을 드롭다운으로 접는다.

### 모바일 390×844

- PLP: 상단바 + 칩 + [필터]·정렬 줄 + 카드 2열 × 1.5줄(두 번째 줄이 걸쳐 보여야 스크롤한다).
- PDP: 이미지(390px 정사각 또는 3:4 이면 약 520px) + 브랜드·상품명·가격이 첫 화면에 걸쳐야 한다. 3:4 이미지로 가격이 밀려나면
  이미지 높이를 화면의 60% 로 제한하는 것을 검토한다. `sticky-buy-bar` 는 항상 보인다.
- 장바구니·주문서: 하단 고정 바에 결제 예정 금액과 버튼이 항상 보인다.

## 4. 와이어프레임

### 4.1 PLP — 데스크톱

```
+--------------------------------------------------------------+
| LOGO  [Search products.................]  Cart(2)  My        |
+--------------------------------------------------------------+
| Home > Women > Outer        Coats  Jackets  Cardigans  >     |
+----------------+---------------------------------------------+
| filter-sidebar | 1,284 items       [Recommended v] [4 | 2]   |
|                | [Free ship x] [~50,000 won x]   reset       |
|                +---------------------------------------------+
| Category       | +--------+ +--------+ +--------+ +--------+ |
| Price          | |        | |        | |        | |        | |
|  [__]-[__]     | |  3:4   | |  3:4   | |  3:4   | |  3:4 <3| |
| Brand          | |        | |        | |        | |        | |
|  [ ] A         | +--------+ +--------+ +--------+ +--------+ |
|  [ ] B         | BRAND      BRAND      BRAND      BRAND      |
| Size           | Name 2ln   Name 2ln   Name 2ln   Name 2ln   |
| Color          | 30% 69,000 15% 8,900  45,000     10% 9,900  |
| Benefit        | coupon     free ship  *4.8(12)   sold out   |
+----------------+---------------------------------------------+
```

`<3` 는 찜. 할인율은 빨강 굵게, 판매가는 굵게, 정가 취소선은 판매가 위 작은 줄(카드 폭이 좁아 생략했다).

## 5. 한국 관례

- **상세 이미지와 텍스트**: 국내 PDP 는 판매자가 만든 세로로 긴 상세 이미지가 핵심이다. 하지만 이미지 속 글자는 화면 낭독기와
  검색이 읽지 못하고, 확대하지 않으면 모바일에서 작다. 소재·사이즈·세탁·구성품·주의사항 같은 핵심 정보는 이미지 앞에 텍스트와
  표로 한 번 더 둔다. 이미지에는 대체 텍스트를 단다.
- **상품 정보 고시**: 상품 종류별로 표시해야 하는 정보(소재, 제조국, 제조사, 품질보증기준 등)를 상품정보 탭 아래 표로 둔다.
  정확한 항목은 법령과 입점 플랫폼 안내를 확인한다.
- **하단 구매 바**: 모바일 PDP 에는 찜 + [구매하기]가 항상 떠 있다. 국내 사용자는 이 바가 있다고 기대한다.
- **리뷰**: 별점 + 구매 옵션 + 체형 정보(키·몸무게·평소 사이즈) + 포토 리뷰가 기본이다. "내 체형과 비슷한 리뷰" 필터와
  사이즈 만족도(작아요·잘 맞아요·커요) 요약이 반품을 줄인다. 체험단·협찬 리뷰는 표시한다.
- **품절·재입고**: 품절 옵션은 목록에서 지우지 말고 회색 + "품절"로 남기고 [재입고 알림] 버튼을 붙인다. 일부 옵션만 품절이면
  옵션 선택지 안에 표시한다.
- **가격 표기**: `30%` 할인율(빨강 굵게) → `69,000원` 판매가(굵게) → `99,000원` 정가(취소선, 회색). 쿠폰 적용가를 따로 보여주려면
  "쿠폰 적용 시 62,100원"처럼 조건을 같이 쓴다.
- **배송**: 배송비, 무료배송 기준, 도착 예정일(오늘출발·내일 도착 같은 약속)은 버튼 근처에 둔다. 제주·도서산간 추가 배송비는
  배송 탭에 적는다.
- **결제**: 카드 + 간편결제(카카오페이·네이버페이·토스페이 등) + 무통장입금(가상계좌)이 기본 묶음이다. 간편결제 버튼은 각 사
  로고·색 가이드를 따른다.
- **주문서**: 배송 메모 선택지, 기본 배송지, 적립금 [전액 사용], 금액이 들어간 결제 버튼, 전체 동의.
- **사업자 정보**: 전자상거래로 판매한다면 푸터에 사업자 정보(상호·대표자·사업자등록번호·통신판매업 신고번호·주소·고객센터 등)를
  표시한다. 정확한 항목은 법령·플랫폼 안내를 확인한다. 마켓플레이스면 판매자 정보를 PDP 배송·교환 탭에 따로 둔다.

## 6. 구조 질문 하나

> **큐레이션형(에디토리얼)인가요, 카탈로그형(밀도)인가요?**

| 선택지 | 바뀌는 것 |
|---|---|
| 큐레이션형 — 상품 수가 적고 브랜드·취향이 핵심 | `product-grid` 3열(데스크톱)·이미지 크게, 카드 정보 최소(브랜드·이름·가격), `hero-media`·`text-block`·`media-text` 로 기획전 이야기를 끼워 넣는다. 배지·쿠폰 표시는 절제 |
| 카탈로그형 — 상품이 많고 가격·조건 비교가 핵심 | `product-grid` 4–5열, 카드에 할인율·배지·리뷰 수, `filter-sidebar` 항목 많이, `sort-bar` 정렬 6종, 행간·여백 촘촘 |
| 혼합 | 홈·기획전은 큐레이션형, 카테고리 PLP·검색은 카탈로그형 |

상품 데이터가 100개 미만이고 브랜드 스토리 콘텐츠가 있으면 큐레이션형을, 필터에 쓸 속성(사이즈·색·가격대)이 풍부하면
카탈로그형을 추론 기본값으로 둔다.

## 8. 콘텐츠가 없을 때

상품 데이터·리뷰·평점을 지어내지 않는다. 예시 상품이 필요하면 "예시 상품" 표시를 달고 실제 카탈로그와 섞지 않는다.

| 섹션 | 없는 것 | 처리 |
|---|---|---|
| `product-card` 리뷰 줄 | 리뷰 | 줄 생략. "리뷰 0" 이나 별 5개 빈 아이콘을 넣지 않는다 |
| `review-summary`, `review-list` | 리뷰 | "첫 리뷰를 남겨 주세요" 한 줄(구매자 대상). 요약 막대는 숨긴다 |
| `pdp-gallery` | 여러 컷 | 한 장이면 썸네일 열을 없앤다. 회색 자리 이미지를 반복하지 않는다 |
| `detail-images` | 상세 이미지 | 텍스트·표 정보 블록만으로 구성(오히려 접근성이 좋다). 비어 있으면 `TODO(상세 정보)` |
| 할인율·정가 | 할인 없음 | 판매가만. 할인율 자리를 비워 두지 않는다 |
| `free-shipping-bar` | 무료배송 기준 | 생략 |
| 배송·교환 탭 | 정책 | 섹션은 두고 내용은 `TODO(정책)`. 정책 없이 오픈하지 않도록 브리프의 콘텐츠 인벤토리에 '필요'로 적는다 |
| 기획전 `hero-media` | 촬영 이미지 | 생략하고 `category-nav` 부터. 큐레이션형인데 이미지가 없으면 `text-block` 타이포 중심 기획전으로 |
