# 진단 체크리스트 (100점 + AI 기본값 지수)

`direct` 1단계에서 지금 화면을 숫자로 읽는 방법. 결과는 브리프 §3 진단 요약과 2단계 방향 옵션의 근거가 되고,
7단계 검증에서 같은 표로 다시 채점한다. **추측한 값으로 채점하지 않는다.** capture `summary.md` 의 실측값이
있으면 그걸 쓰고, 없으면 코드에서 센 값에 "코드 기준"이라고 적는다.

## 1. 수집

**스크린샷이 있을 때(권장)** — before 캡처의 `summary.md` 를 먼저 읽는다. 타이포 표(역할별 크기·행간·자간),
색 역할과 대비 결과, 간격(기준 단위·섹션 여백·adherence), radius·그림자, 모션(reduced-motion), 구조, 가로 넘침 줄
(`health.overflowX`)이 거의 모든 칸을 채운다. 그다음 `desktop.png`·`mobile.png` 를 보고 위계·정렬·상태를 판단한다.

**코드에서 셀 때** — 대상 페이지와 그 섹션 컴포넌트만 Grep 한다(`components/ui/*` 원본은 빼고).

| 무엇 | 읽는 법 |
|---|---|
| 임의 px 값 | Tailwind arbitrary value. 많을수록 스케일 밖 |
| px 값 전체 | 4 의 배수가 아닌 값의 비율을 센다(1·2px 경계는 뺀다) |
| 글자 크기 종류 | 서로 다른 값의 개수 |
| 행간 | 본문 요소의 값 |
| hex 색 | 중립·의미색을 뺀 hue 개수 |
| 포커스 | outline 을 지우고 대체가 없으면 0점 |
| 한국어 | 한국어 규칙 칸 |

패턴은 한 줄이 Grep 정규식 하나다. 콜론 뒤를 그대로 복사해 넣는다.

```text
임의 px 값:     \[\d+(\.\d+)?px\]
px 값 전체:     \b\d+(\.\d+)?px\b
글자 크기 종류:  text-(xs|sm|base|lg|[2-9]?xl)\b|text-\[\d+px\]|font-size:
행간:           leading-[\w\[\].]+|line-height:
hex 색:         #[0-9a-fA-F]{3,8}\b
포커스:          focus-visible|outline-none|outline:\s*none
한국어:          keep-all|break-keep|lang=
폰트 선언:       font-family|@font-face|next/font
```

그리고 `node "${CLAUDE_PLUGIN_ROOT}/scripts/dd.mjs" tells <페이지 파일…> <전역 CSS> <레이아웃>` 으로 AI 기본값 패턴을 센다.
이 문서의 `${CLAUDE_PLUGIN_ROOT}` 는 치환되지 않은 표기다. 명령은 SKILL.md 에 적힌 실제 경로를 따옴표째 쓴다.

## 2. 8개 차원 (100점)

각 검사는 0·1·2점. 차원 점수 = 가중치 × (얻은 점수 ÷ 최대 점수), 소수 첫째 자리에서 반올림. 판단할 수 없는
검사(예: 모바일 캡처가 없을 때의 390px 가로 넘침)는 빼고 최대 점수를 줄인다.

### 위계 15
| 검사 | 2 | 1 | 0 |
|---|---|---|---|
| display ÷ body | 랜딩 ≥ 3.0 / 앱 ≥ 1.6 | 랜딩 2.0–3.0 / 앱 1.3–1.6 | 그 아래 |
| 첫 화면 초점 | 주인공 1개(약속 또는 제품) + 주 CTA 1개 | 둘이 경쟁 | 없음 또는 셋 이상 |
| 헤딩 단계 구분 | h1·h2·h3 이 서로 1.2배 이상 차이 | 한 쌍이 붙음 | 두 쌍 이상 붙음 |

### 정렬 10
| 검사 | 2 | 1 | 0 |
|---|---|---|---|
| 블록 안 정렬 축 | 하나(왼쪽 또는 가운데) | 섹션 사이에 섞임 | 한 블록 안에서 섞임 |
| 컨테이너 폭 | 하나(풀블리드는 의도한 곳만) | 이유 있는 2개 | 섹션마다 다름 |

### 간격 15
| 검사 | 2 | 1 | 0 |
|---|---|---|---|
| 스케일 밖 값 비율 | ≤ 5% | ≤ 15% | > 15% |
| 섹션 간격 (랜딩) / 그룹 간격 (앱) | ≥ 80px(모바일 ≥ 48) / ≥ 24px | 48–80 / 16–24 | < 48 / < 16 |
| 안쪽:바깥 간격 | 모든 그룹에서 안쪽 ≤ 바깥의 1/2 | 일부 위반 | 안쪽 ≥ 바깥(묶음이 안 읽힘) |

### 대비 15
| 검사 | 2 | 1 | 0 |
|---|---|---|---|
| 본문 텍스트 | ≥ 7:1 | 4.5–7:1 | < 4.5:1 |
| 보조 텍스트·placeholder | ≥ 4.5:1 | 3–4.5:1 | < 3:1 |
| 컨트롤 경계·포커스 링 | 모두 ≥ 3:1 | 일부 | 컨트롤이 배경에 묻힘 |

### 타이포 15
| 검사 | 2 | 1 | 0 |
|---|---|---|---|
| 글자 크기 종류 | ≤ 6 | 7–9 | ≥ 10 |
| 본문 행간·줄 길이 | 행간 한국어 1.5–1.8(라틴 1.4–1.7), 한 줄 ≤ 40em | 하나 벗어남 | 둘 다 벗어남 |
| 한국어 규칙 (한국어 페이지) | keep-all + 한글 웹폰트 + 양수 자간 없음 | 하나 빠짐 | 둘 이상 빠짐 |
| 패밀리·굵기 (라틴 전용 페이지) | 패밀리 ≤ 2, 굵기 ≤ 3 | 하나 넘침 | 둘 다 넘침 |

### 색 10
| 검사 | 2 | 1 | 0 |
|---|---|---|---|
| 의미색 뺀 유채색 hue 수 | ≤ 2 | 3 | ≥ 4 |
| 강조색 쓰임 | 행동·핵심 정보에만 | 장식에 1–2곳 | 곳곳에 |

### 상태 10
| 검사 | 2 | 1 | 0 |
|---|---|---|---|
| focus-visible | 모든 인터랙티브 요소에 보이는 링 | 브라우저 기본만, 또는 일부 | `outline: none` 에 대체 없음 |
| 상태 설계 (hover·active·disabled·loading·empty·error 중 해당하는 것) | 5개 이상 | 3–4개 | 2개 이하 |

### 반응형 10
| 검사 | 2 | 1 | 0 |
|---|---|---|---|
| 390px 가로 넘침 (summary `가로 넘침` 줄의 mobile 값) | 0 | 1–16px | > 16px |
| 모바일 글자·터치 | 본문 ≥ 15px, 입력 ≥ 16px, 터치 ≥ 44px | 본문 14px 이상 15px 미만, 터치 24–44px, 입력 < 16px 중 하나 | 터치 < 24px 또는 본문 < 14px |

## 3. AI 기본값 지수 (점수와 따로)

`dd.mjs tells` 결과의 `summary`(S1·S2·S3 개수)에 스크린샷 시각 확인으로 찾은 tell 을 더해 **따로** 보고한다.
100점에 섞지 않는 이유: 점수는 "잘 읽히고 쓰기 좋은가", tell 은 "누구 것인지 보이는가"를 잰다. 깔끔하지만
전형적인 화면(90점, S1 4개)이 흔하고, 둘은 처방도 다르다.

- 코드에서 잡힌 것은 ID·파일·줄로, 시각 확인으로 찾은 것은 ID·화면 위치로 적는다.
- 브리프가 이름으로 고른 요소는 세지 않는다(브리프 우선).
- 정의·처방은 `${CLAUDE_PLUGIN_ROOT}/references/ai-default-tells.md`.

## 4. 채팅 출력

점수 표 전체가 아니라 **점수 + 상위 문제 3개 + tell 요약**을 레버 언어와 숫자로 낸다. 문제마다 "왜 그렇게
느껴지는지"를 느낌어로 이어 준다 — 사용자가 다음에 그 단어 대신 레버를 말할 수 있게.

```
진단 48/100 · AI 기본값 S1 3 · S2 2
1. 위계 약함 — 헤드라인 36px vs 본문 16px (2.25배). 랜딩 기준 3배 이상 → display 48–56px
2. 간격 불규칙 — px 값 37% 가 4 의 배수가 아님, 섹션 간격 32–40px → 4·8 스케일, 섹션 96px
3. 모든 섹션이 같은 3열 카드(LA-1·LA-2) — 기능 무게가 같아 보임 → 핵심 기능 1개를 실제 화면과 함께
tell: CO-1 보라 그라데이션(hero.tsx:12), TY-2 eyebrow ×4, IC-1 이모지 아이콘 ×3, MO-1, CP-1
```

## 5. 문제 → 느낌어 역매핑

사용자가 느낌어로 말했다면 진단 결과를 그 말에 연결해서 설명한다("이게 답답해 보이는 이유").

| 진단 결과 | 사용자가 흔히 하는 말 |
|---|---|
| 본문 행간 < 1.5, 섹션 간격 < 48px, 테두리 상자 많음 | 답답해, 복잡해 |
| 섹션 간격 > 160px 인데 콘텐츠가 적음, 주인공 없음 | 휑해, 밋밋해 |
| display ÷ body < 2, 굵기 1–2종 | 밋밋해, 없어 보여 |
| 강조색 ≥ 4, 정렬 축 섞임, 글자 크기 ≥ 10종 | 산만해, 유치해 |
| 한글 웹폰트 없음(맑은 고딕 폴백), 고채도 원색 | 촌스러워, 올드해 |
| 간격 스케일 밖 > 15%, 이미지 톤 제각각, 과장 카피 | 싸 보여 |
| 본문 대비 < 4.5:1, 한 줄 > 45em | 안 읽혀 |
| tell S1 ≥ 2 | AI 티 나 |
| 차가운 회색뿐, radius 0–4, 공문체 카피 | 딱딱해, 차가워 |
