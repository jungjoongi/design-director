# 스크린샷에서 값 추정하기 (Vision Estimation)

이미지만 있을 때(사다리 2칸, 캡처 R3·R5, exit 8) 읽는다. 픽셀은 CSS 를 알려주지 않는다. 그래서 여기서 나온 값은 모두
`추정`이고, 단정하지 않고 범위나 스냅한 값으로 쓴다. 끝에는 위 칸으로 오르는 방법을 한 줄 제안한다:
"URL 을 주시면 실제 CSS 값으로 다시 잴 수 있어요."

## 1. 뷰포트와 DPR 부터 정한다

이미지 폭을 CSS 픽셀로 바꿔야 모든 수치가 맞는다. CSS px = 이미지 px ÷ DPR.

| 이미지 폭 | 가능성이 큰 해석 | 확인할 것 |
|---|---|---|
| 2880 | 1440 @2x (Mac 레티나 데스크톱) | 본문이 32px 안팎으로 보이면 맞다 |
| 2560 | 1280 @2x | |
| 1920 | 1920 @1x 또는 960 @2x | 내비 높이로 가른다 |
| 1440 · 1280 | @1x 데스크톱 | |
| 1170 · 1179 | 390 · 393 @3x (iPhone) | 상태 바·홈 인디케이터가 있으면 확실 |
| 1290 · 1125 | 430 · 375 @3x | |
| 750 · 828 | 375 · 414 @2x | |
| 1080 | 360 @3x 안팎 (Android) | DPR 이 2.625 처럼 소수일 수 있다 |

폭이 표에 없으면 잘린 이미지다. 2장의 기준 크기로 배율을 푼다.

## 2. 기준 크기로 배율을 확인한다

알려진 UI 크기와 맞춰 보면 DPR 추측이 맞는지 알 수 있다.

| 기준 | 흔한 범위(CSS px) |
|---|---|
| 데스크톱 버튼 높이 | 36–48 |
| 모바일 주 버튼 높이 | 48–56 |
| 데스크톱 내비 높이 | 56–80 |
| 모바일 상단 바 | 44–56 |
| iOS 상태 바 / 탭 바 / 홈 인디케이터 영역 | 44–59 / 49 / 34 (pt) |
| 본문 글자 | 14–18 |
| 아이콘 | 16 / 20 / 24 |

- **글자 크기**는 줄 간격으로 역산하는 게 가장 안정적이다. 여러 줄 본문에서 기준선 사이 거리(baseline pitch)를 재고,
  행간 1.5–1.7 을 가정해 나눈다. 예: 기준선 간격 27px → 행간 1.6 이면 약 17px, 1.5 면 18px → "17–18px (추정)".
- 라틴 글자가 있으면 대문자 높이가 대략 0.7em, x-height 가 0.5–0.55em 이다. 한글만 있으면 줄 간격 방법을 쓴다.

## 3. 간격은 4·8 격자로 스냅한다

잰 값을 가장 가까운 격자 값으로 반올림해서 적는다: 4, 8, 12, 16, 24, 32, 40, 48, 64, 80, 96, 128, 160.
"약 64px (추정, 8 스냅)"처럼 스냅했다는 걸 밝힌다. 섹션 여백은 배경 경계·제목 위치 사이 거리로 잰다.
radius 는 큰 이미지에서도 ±2px 오차가 난다. 0 / 4–8 / 12–16 / 20 이상 / pill 단계로 적는다.

## 4. 색은 계열과 대략의 hex 로

- 스크린샷 색은 틀어진다: JPEG 압축·크로마 서브샘플링, Mac 의 Display P3 캡처가 sRGB 로 변환될 때의 차이, 다크 모드,
  오버레이·글래스 효과, 반투명 위 합성색.
- 글자·경계의 안티앨리어싱을 피해서 **넓고 평평한 면의 가운데**에서 색을 본다.
- hue 계열 + 대략의 hex 로 적는다: "차가운 거의 검정 — 대략 #0E1013 (추정)". 순수 검정인지 `#111` 같은 근사 검정인지는
  JPEG 에서 가를 수 없다. 그 차이가 중요한 판단(CO-6 등)이면 "확인 불가"로 둔다.
- 그라데이션은 양 끝 색과 방향만. 그림자는 오프셋·흐림·진하기를 범위로("아래 8px, 흐림 24px 안팎, 아주 옅음").

## 5. 픽셀로는 알 수 없는 것

| 항목 | 대신 쓰는 것 |
|---|---|
| 글꼴 이름 | 분류(neo-grotesk · geometric · humanist · 명조 · 둥근 고딕) + 후보 2–3개, "후보"라고 밝힌다 |
| 모션·hover·focus 상태 | "확인 불가". 화면에 보이는 단서(포커스 링 등)만 적는다 |
| 반응형 동작 | 받은 폭에서 보이는 것만. 다른 폭은 "확인 불가" |
| 정확한 CSS(변수 이름, 그림자 레이어) | 범위로 |
| 스크롤 아래 내용 | 받은 이미지에 있는 범위만 구조 표에 넣는다 |

## 6. 신뢰도 문구와 frontmatter

| 문구 | 쓰는 때 |
|---|---|
| "약 16px (추정, ±2px)" | 기준 크기로 배율을 확인한 크기 |
| "16–18px (추정)" | 배율이 불확실할 때 |
| "확인 불가" | 픽셀로 알 수 없는 것. 칸을 비우지 않는다 |

- frontmatter 는 `${CLAUDE_PLUGIN_ROOT}/references/profile-schema.md` 의 "입력 종류별로 달라지는 키" 표를 따른다. 이미지 입력이면
  `method: vision`, `shots: none`, `confidence: medium` 또는 `low`, `evidence` 는 대부분 `estimated`. R3 캡처면 capture-guide 의
  `method: mcp`·`shots: session-only` 다.
- 대화에 붙인 이미지는 세션이 끝나면 다시 볼 수 없다. **부록: 화면 관찰**을 지금 자세히 쓴다. 나중에 비교할 기억은 그것뿐이다.
- tokens.json 은 만들지 않는다(엔진 산출물이다). 값은 프로필 표에만 `추정` 으로 남는다.

## 7. 이미지 여러 장과 긴 이미지

- 같은 페이지를 스크롤하며 찍은 여러 장이면 위에서부터 순서대로 보고 한 페이지로 이어서 구조를 만든다.
- 데스크톱과 모바일이 같이 있으면 모바일 변화(열 수, 이미지 위치, 고정 버튼)를 7장에 적는다.
- 세로로 아주 긴 전체 페이지 한 장은 읽을 때 축소돼 작은 글자가 뭉개진다. 구조는 거기서 잡고, 수치는 화면 단위 스크린샷을
  따로 달라고 한다.
- 위에서 아래로 한 화면 높이씩 훑으며 섹션 경계(배경색 변화, 큰 여백, 새 제목)를 찾는다. 구조 표 만드는 법은
  `page-anatomy.md`.
