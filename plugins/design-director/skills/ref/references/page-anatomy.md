# 페이지 구조 읽기 (Page Anatomy)

ref 5단계에서 프로필 7장 "페이지 구조"를 만들 때 읽는다. 결과물은 섹션 표 + 축약 ASCII + 모바일 변화 + 리듬 한 줄이고,
frontmatter `structure` 에 시퀀스 한 줄을 남긴다. id 는 `${CLAUDE_PLUGIN_ROOT}/references/sections.md` 에서만 고른다.

## 1. 재료

- **URL 캡처**: summary.md 의 구조 줄(`02 hero-split  y64 h880  h1 "…"  buttons 2  media right (0.82)`), 시퀀스 한 줄,
  모바일 변화 줄 + `overview.jpg`, 필요할 때 `slices/desktop-NN.jpg`.
- **이미지**: 위에서 아래로 한 화면 높이씩 훑으며 경계(배경색 변화, 큰 여백, 새 제목, 열 수 변화)를 찾는다.
- 구조 줄의 따옴표 안 제목은 사이트 원문이다. 섹션을 이해하는 데만 쓰고 프로필에 옮기지 않는다.

## 2. 절차

1. 엔진 목록을 출발점으로 삼고, 섹션마다 스크린샷과 맞춰 본다.
2. 신뢰도 0.5 미만이거나 `unknown` 이면 스크린샷을 보고 정한다. 엔진의 `alt` 가 맞으면 그걸 쓴다.
3. 엔진이 두 섹션을 하나로 묶었으면 표에서 나누고, 비고에 "엔진 미분리"라고 적는다.
4. 앱 화면 id(`app-shell`, `sidebar-nav` 등)처럼 엔진이 감지하지 않는 id 는 Claude 가 붙인다.
5. **tokens.json 은 고치지 않는다.** 정정은 표의 비고에 적는다: "엔진 feature-grid(0.41) → bento-grid: 타일 크기가 다르다".
6. 맞는 id 가 없으면 가장 가까운 id + 변형 메모. 새 id 를 만들지 않는다.

## 3. 섹션 한 줄 묘사

레이아웃 한 줄에는 열 구성, 정렬, 미디어 위치, 반복 수, 특이한 처리를 담는다. 형용사 대신 배치와 수로 쓴다.

| 나쁜 예 | 좋은 예 |
|---|---|
| 멋진 히어로 | 5/7 분할, 왼쪽 h1 2줄 + 버튼 2, 오른쪽 제품 화면이 컨테이너 밖으로 넘침 |
| 기능 소개 | 3열 카드 gap 24, 아이콘 없이 제목 + 설명 + 작은 화면 |
| 고객 후기 | 인용 2개 2열, 사진 없이 이름·팀, 세리프 인용문 |
| 큰 이미지 | 풀블리드 사진, 왼쪽 아래 흰 글자 h2 + 텍스트 링크 |

## 4. 리듬과 배경

- 섹션 상하 여백(summary 의 D/M 값)과 배경 교차 패턴을 한 줄로: "리듬: 여백 144/88 고정, 흰 배경 연속, how-it-works·footer 만
  옅은 회색, cta-band 만 진한 면".
- 배경 교차가 페이지를 몇 막으로 나누는지 본다. 명도 변화가 3번 이하면 여백이 구획을 맡고, 매 섹션 교차면 배경이 맡는다.

## 5. 모바일 변화

summary 의 모바일 줄과 `mobile.png` 로 적는다. 흔한 변화:

- 열 수: 3열 → 1열, 상품 4열 → 2열
- 미디어 위치: 오른쪽 이미지가 h1 아래로, 넘침(bleed)이 사라짐
- 내비: 링크 → 햄버거, 주 CTA 는 남거나 하단 고정 버튼으로
- 가로 스크롤 칩·카드, 하단 고정 바(`sticky-buy-bar` 등) 등장
- 여백·글자 축소 비율(섹션 144 → 88, h1 64 → 40)

## 6. 표 형식

| # | id | 레이아웃 한 줄 | 배경 | 비고 |
|---|---|---|---|---|
| 1 | nav | 로고 왼쪽, 링크 4 + 주 CTA 오른쪽, 64px sticky | bg | |
| 2 | hero-split | 5/7 분할, 오른쪽 제품 화면이 컨테이너 밖으로 넘침 | bg | 엔진 hero-product(0.46) → hero-split |

배경 열은 색 역할 이름(bg, surface, bg-inverse, 사진)으로 쓴다. 시퀀스는 반복 수를 괄호로:
`nav → hero-split → logo-cloud → feature-alternating(3) → … → footer`.

## 7. 축약 ASCII 규칙

터미널과 마크다운 어디서나 정렬이 맞아야 direct 가 그대로 가져다 쓴다.

- **ASCII 문자만** 쓴다: `+ - | [ ] ( ) /`. 선 그리기 문자(─ │ ┌)는 한국어 환경 터미널에서 두 칸으로 그려질 수 있어 정렬이 깨진다.
- **박스 안은 영문만**: 섹션 id 와 짧은 영문 메모(`(3)`, `5/7`, `bleeds right`). 한글은 두 칸을 차지하니 박스 밖 메모로 쓴다.
- **폭 64자 이하**, **모든 줄의 글자 수를 같게** 맞춘다. 오른쪽 `|` 가 한 줄이라도 어긋나면 다시 센다.
- 섹션 하나에 1–2줄. 열은 `|` 로 나누고, 비율은 대략이면 된다.
- 명도가 바뀌는 곳(배경 교차)에만 가로선을 넣으면 리듬이 같이 보인다.

```text
+--------------------------------------------------------------+
| nav                                        links(4)  [cta]   |
+--------------------------------------------------------------+
| hero-split    h1 + lead + 2 buttons | product shot, bleeds   |
| logo-cloud (6)                                               |
| feature-alternating (3)       text 5 | screen 7, swapped     |
+--------------------------------------------------------------+
| how-it-works (3 steps)                         bg surface    |
+--------------------------------------------------------------+
| testimonials (2)  /  pricing (3)  /  faq (6)                 |
+--------------------------------------------------------------+
| cta-band                                       bg inverse    |
+--------------------------------------------------------------+
| footer (4 cols + business info)                bg surface    |
+--------------------------------------------------------------+
```

박스 밖 메모 예: "히어로 제품 화면이 오른쪽 끝까지 넘친다. 모바일에선 h1 아래로 내려가고 넘침이 없다."
