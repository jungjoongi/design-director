## 정의

한 화면에 메시지 하나, 행동 하나만 둔다. 큰 숫자와 짧은 해요체 문장이 주인공이고, 파랑 계열 하나가 행동을 표시한다.
깊이는 그림자가 아니라 **회색 배경 단계**(페이지는 옅은 회색, 카드는 흰색)로 만들고, 정보는 리스트 행(아이콘 + 두 줄 텍스트
+ 값이나 화살표)으로 쌓는다. 모바일이 먼저이고, 주 행동은 화면 아래에 고정된 전폭 버튼이다.

흔한 오해: "토스 = 파랑 + 둥근 카드"가 아니다. 파랑과 radius 만 가져오면 평범한 SaaS 카드 키트가 된다. 이 스타일을 만드는 건
**화면당 메시지 수, 숫자의 크기, 그림자 없는 배경 단계, 해요체**다.

## 시그니처 무브

1. **한 화면에 메시지 하나, 행동 하나** — 제목 한 문장 + 주 버튼 하나. 두 번째 행동은 텍스트 버튼으로 낮춘다.
2. **숫자를 가장 크게** — 금액·결과 28–48px 굵기 700, 단위 "원"은 본문 크기로.
3. **그림자 대신 배경 단계** — 명도 95–97% 회색 페이지 위에 흰 카드, radius 16–24px, 테두리·그림자 없음.
4. **정보를 리스트 행으로** — 왼쪽 아이콘 32–40px + 제목·보조 두 줄 + 오른쪽 값이나 chevron, 행 높이 56–72px.
5. **주 행동을 하단 고정 전폭 버튼으로** — 높이 52–56px, 좌우 20px, `padding-bottom: env(safe-area-inset-bottom)`.
   뷰포트 메타에 `viewport-fit=cover` 가 있어야 값이 들어온다: `<meta name="viewport" content="width=device-width, initial-scale=1, viewport-fit=cover">`.

## 잘 맞는 곳 / 안 맞는 곳

- 잘 맞는 곳: 금융·결제·송금, 보험, 공공·행정 모바일, 예약·신청 흐름, 설정 화면, 모바일 웹앱.
- 안 맞는 곳: 데스크톱 정보 밀집 대시보드, 브랜드 스토리텔링 랜딩, 패션·감성 커머스, 긴 읽기 콘텐츠.

## 흔한 실수

- 파랑 그라데이션 카드 + 카드마다 그림자 — CO-1, SH-2. 핵심은 배경 단계다.
- 카드·버튼·시트가 모두 같은 radius — SH-1
- 한 화면에 버튼 두세 개, "시작하기" + "더 알아보기" — CP-6
- 이모지를 기능 아이콘으로 — IC-1
- "~하시겠습니까?" 같은 번역투·합쇼체 UI — KR-7
- 상승을 초록, 하락을 빨강으로 — KR-6

## 한국어 노트

- 해요체 UI 카피: "송금할게요", "확인했어요". 버튼은 짧은 동사형("다음", "확인", "보내기").
- 금액은 천 단위 쉼표 + "원", 큰 금액은 "만·억"을 함께 쓴다. 상승 빨강, 하락 파랑.
- 본인인증, 약관 전체 동의(`agree-all`)가 관례다. 전체 동의 + 개별 펼침.
- 입력 필드 글자는 16px 이상(iOS 자동 확대 방지).
- 숫자는 `tabular-nums` 로 자릿수를 맞춘다. count-up 은 결과 숫자 한 곳에만.
