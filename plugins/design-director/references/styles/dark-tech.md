# 다크 테크 (Dark Tech) — id: dark-tech

별칭: 다크 모드 SaaS, 개발자 도구 느낌, Linear 스타일, 테크 느낌, dark UI, devtool aesthetic
축: 밀도 3 · 온도 1 · 채도 2 · 대비 4 · 둥긂 2 · 장식 2
대표 레퍼런스: Linear (linear.app), Raycast (raycast.com), Supabase (supabase.com) (정성, 미검증)

## 정의

거의 검정에 가까운 무채색 면 위에서 1px 반투명 경계와 미세한 명도 단계로 깊이를 만들고, 자간을 조인 산세리프 헤드라인과
실제 제품 UI 로 "정밀한 도구"를 표현한다. 빛(glow)·그라데이션은 한두 곳의 절제된 포인트로만 쓴다.

AI 기본값 2번 묶음(거의 검정 + 형광 강조 하나, CO-3)과 겉모습이 닮았다. 가르는 기준은 **면의 단계와 경계**다. dark-tech 는
배경·면·경계가 3–4단계로 설계돼 있고, 기본값은 검정 한 장 위에 형광색 하나만 있다.

## 시그니처 무브

1. **그림자 대신 1px 반투명 경계로 면을 나눈다** — `border: 1px solid rgb(255 255 255 / 0.08)`.
2. **배경을 명도 3단계로 쌓는다** — bg / surface / surface-2 를 명도 +2 ~ +4%씩, 같은 hue 로.
3. **헤드라인을 조이고 굵기를 낮춘다** — 굵기 500–600, 자간 -0.02 ~ -0.04em(한글은 -0.03em 까지). 굵은 700 대신 크기로 위계를 낸다.
4. **텍스트를 흰색 알파로 단계화한다** — 제목 90%, 본문 70–80%, 보조 55–60%. 보조도 대비 4.5:1 이상.
5. **빛은 한 곳에만** — 히어로 제품 화면 뒤 glow 하나, 강조색 알파 15–30%.

## 잘 맞는 곳 / 안 맞는 곳

- 잘 맞는 곳: 개발자 도구, 인프라·API, AI 제품, 생산성 앱, 게임 런처.
- 안 맞는 곳: 일반 소비자(특히 고연령), 긴 읽기 콘텐츠, 식음료·웰니스, 밝은 신뢰가 필요한 금융.

## 흔한 실수

- 검정 한 장 + 형광 초록·주황 강조 하나 — CO-3
- 근거 없는 `#0B0B0B`·`#111` 검정 — CO-6
- 보라→파랑 그라데이션, 그라데이션 글자 헤드라인 — CO-1, TY-3
- 뒤에 아무것도 없는데 글래스 — SH-3
- 데이터 라벨을 모노로 — TY-5. 마퀴·커서 glow — MO-3
- 흰 40% 본문 — CO-7

## 한국어 노트

- 어두운 바탕에서 한글은 번져 보인다(halation). 본문 굵기 400 을 유지하고 행간 1.6 이상, 텍스트는 흰 85–90%.
- 한글 헤드라인 자간은 -0.02 ~ -0.03em 까지. 라틴처럼 -0.04em 으로 조이면 받침이 붙는다.
- 한국 사용자 상당수가 라이트 모드를 쓴다. 다크 단독으로 갈지, 라이트 토큰도 만들지 정한다.
- 영문 제품 용어가 섞이면 라틴 서체를 font-family 앞에 두고 한글 고딕을 뒤에 둔다. 두 서체의 높이가 맞는지 확인한다.
