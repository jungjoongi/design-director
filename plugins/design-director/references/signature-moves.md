# 시그니처 무브 (Signature Moves)

ref 의 3단계와 direct 의 브리프 4장이 쓴다. 프로필에서 가장 중요한 장이다. 토큰 표가 "무엇이 있나"라면, 무브는 "그중
무엇이 이 느낌을 만드나"다.

## 1. 정의

시그니처 무브는 **화면에서 관찰할 수 있고, 수치로 지시할 수 있는 디자인 결정**이다. 그 결정을 웹 기본값으로 바꾸면 페이지가
더 이상 레퍼런스처럼 보이지 않는다.

- 관찰 가능: 어디에 있는지 가리킬 수 있다(히어로 h1, 모든 섹션 경계, 주 버튼).
- 지시 가능: 레버와 수치로 쓸 수 있다(`letter-spacing: -0.03em`, radius 0, section padding 160px).
- 결정적: 빼면 느낌이 무너진다.

"깔끔하다"는 결과이고 무브는 그 원인이다. 무브를 찾는다는 건 그 원인에 이름을 붙이는 일이다.

## 2. 찾는 다섯 렌즈

| 렌즈 | 하는 법 | 잘 걸리는 것 |
|---|---|---|
| 실눈 테스트 (squint test) | overview.jpg 를 작게 보거나 실눈으로 본다. 형태만 남았을 때 무엇이 보이나 | 덩어리 대비, 여백 리듬, 가장 큰 요소, 명도 패턴 |
| 빼기 테스트 (subtraction test) | 그 요소를 머릿속에서 웹 기본값으로 바꿔 본다. 느낌이 사라지면 무브다 | 타이포 처리, 색 제한, 깊이 표현 |
| 기본값 대비 편차 | 아래 3장 표와 비교한다. 2배 이상 차이 나거나 방향이 반대면 후보 | 여백, 자간, radius, 그림자 |
| 반복 3회 이상 | 같은 결정이 세 군데 이상 나오면 우연이 아니라 시스템이다 | 경계 처리, 강조색 사용처, 이미지 크롭 |
| 레버로 표현 가능 | CSS 속성이나 토큰 하나로 쓸 수 있나 | 형용사만 남으면 탈락 |

후보를 6–10개 모은 뒤 빼기 테스트·반복·레버 표현으로 거르고, 영향이 큰 순서로 3–5개를 남긴다.

## 3. 웹 기본값 표 (편차를 재는 기준)

| 레버 | 흔한 기본값 | 무브가 되는 편차 예 |
|---|---|---|
| 본문 크기·행간 | 16px / 1.5 | 18–20px / 1.7(읽기형), 13–14px / 1.4(밀집형. 한글은 표 셀만 1.4, 본문은 1.5 이상) |
| 헤드라인 자간 | 0 | -0.02 ~ -0.04em(조임), +0.1em 이상(넓힘) |
| 서체 | Inter·system-ui 하나 | 세리프 제목, 전용 서체, 굵기 폭이 넓은 가변 서체 |
| radius | 모든 곳 8px | 0, 20px 이상, 위계별 단계 |
| 그림자 | `shadow-md` (rgba(0,0,0,.1)) | 없음, 하드 오프셋, 1px 경계로 대체 |
| 섹션 여백 | 64–96px | 144px 이상, 32–48px |
| 컨테이너 | 1200–1280px 가운데 | 960px, 풀블리드, 비대칭 bleed |
| 기능 소개 | 아이콘 + 제목 + 설명 3열 카드 | 실제 화면 교차 행, 표, 벤토 |
| 강조색 | 파랑·보라 하나 + 그라데이션 | 강조 없음, 상태 하나에만, 원색 면 |
| 정렬 | 모든 섹션 가운데 정렬 | 일관된 왼쪽 정렬, 비대칭 |
| 모션 | 모든 섹션 fade-up 300ms | 없음, 한 번의 연출, 상태 변화만 |

## 4. 작성 형식

```markdown
### 2. 섹션을 선이 아니라 여백으로만 나눈다
- 관찰: 모든 섹션 경계(overview.jpg 전체). 배경색 교차·구분선 없음
- 수치: section padding-y 144px(측정, desktop) / 88px(측정, mobile)
- 기본값과의 차이: 일반 랜딩 64–96px 대비 1.5–2배
- 따라 하는 법: `--space-section: clamp(88px, 10vw, 144px);` 섹션에 border·배경 교차를 두지 않는다
- 깨지는 경우: 콘텐츠가 짧은 섹션은 휑해진다 → 섹션 수를 줄이거나 두 섹션을 합친다
```

- **제목**: 동사로 끝나는 지시문("나눈다", "조인다", "쓴다"). 명사구("여백의 미")는 쓰지 않는다.
- **관찰**: 어느 화면, 어느 요소인지. 파일 이름(desktop.png, overview.jpg)이나 섹션 id 를 쓴다.
- **수치**: 하나 이상, 근거 태그를 괄호로(측정·선언·파생·추정·카탈로그). 수치가 없으면 무브가 아니다.
- **기본값과의 차이**: 3장 표 기준으로 얼마나, 어느 방향으로 다른지.
- **따라 하는 법**: CSS 나 Tailwind 한 줄. 다른 프로젝트에 그대로 옮길 수 있게.
- **깨지는 경우**: 이 무브가 실패하는 조건과 대응. 콘텐츠 조건(실제 제품 화면이 있어야 함 등)도 여기에 쓴다.

## 5. 나쁜 예 → 좋은 예

| 나쁜 예 | 왜 안 되나 | 좋은 예 |
|---|---|---|
| 깔끔하고 모던하다 | 결과 형용사다. 레버가 없다 | 섹션을 선·카드가 아니라 여백으로만 나눈다: padding 160px(측정), 배경 교차 없음 |
| 타이포가 세련됐다 | 무엇을 바꾸면 되는지 모른다 | 헤드라인을 크게 조인다: h1 72px / 1.05, 자간 -0.03em(측정), 본문 16px 과 4.5배 차이 |
| 색감이 고급스럽다 | 색 이름도 면적도 없다 | 무채색 6단계에 강조색 하나를 주 CTA 에만 쓴다: 강조 면적 2% 미만(측정) |
| 그림자가 부드럽다 | 값이 없고, 실제로는 그림자가 아닐 수 있다 | 그림자 대신 배경 단계로 깊이를 만든다: 회색 페이지 위 흰 카드, shadow none(측정) |
| 애니메이션이 자연스럽다 | 무엇이 언제 움직이는지 없다 | 상태가 바뀔 때만 움직인다: 200ms ease-out, 스크롤 등장 연출 없음(측정) |
| 사진이 감성적이다 | 재현할 수 없다 | 사진을 가장자리까지 채우고 글자는 13px 로 줄인다: 이미지 비중 46%(측정), radius 0 |

## 6. 레버별 무브 원형

브랜드와 상관없는 일반 원형이다. 실제 수치는 측정값으로 채운다.

| 레버 | 원형 | 흔한 수치 범위 | 깨지는 경우 |
|---|---|---|---|
| 타입 | 헤드라인을 크게 조이고 굵기를 낮춘다 | display 64–96px, 굵기 500–600, 자간 -0.02 ~ -0.04em·행간 1.0–1.1(라틴), 한글은 자간 -0.02 ~ -0.03em·행간 1.15 이상 | 한글을 -0.03em 넘게 조이면 받침이 붙고, 행간 1.15 아래면 두 줄 제목의 받침과 초성이 부딪힌다 |
| 타입 | 본문을 한 단계 키우고 줄을 짧게 한다 | 본문 18–20px, 행간 1.7–1.8, 한 줄 34–40em(한글) | 앱 화면에선 정보가 화면 밖으로 밀린다 |
| 색 | 무채색으로 다 하고 강조색은 한 곳에만 쓴다 | 강조 면적 1–5%, 쓰임 1–2곳 | 강조가 오류색과 겹치면 의미가 섞인다 |
| 색·깊이 | 그림자 대신 배경 단계로 깊이를 만든다 | 배경 단계 2–3개, 명도 차 3–6% | 흰 배경 위에 흰 카드면 경계가 사라진다 |
| 공간 | 섹션을 여백으로만 나눈다 | 섹션 여백 기본값의 1.5–2배 | 짧은 섹션이 휑해진다 |
| 공간 | 정보를 촘촘히 쌓는다 | 행 32–36px, 본문 13–14px, gap 8–12px | 마케팅 첫 화면에 쓰면 답답하다 |
| 형태 | 모서리를 하나의 결정으로 묶는다 | radius 0–2 전부, 또는 위계별 2–3단계(`inner = outer - padding`) | 모든 곳 같은 값이면 SH-1 |
| 깊이 | 그림자 대신 1px 경계로 면을 나눈다 | 1px, 텍스트색 알파 6–12% | 밝은 배경에서 경계가 너무 옅으면 면이 붙어 보인다 |
| 모션 | 상태가 바뀔 때만 움직인다 | 120–200ms ease-out, 등장 연출 0–1곳 | 첫인상이 심심할 수 있다 → 연출은 히어로 한 번만 |
| 이미지 | 실제 제품 화면을 증거로 크게 둔다 | 화면 폭 50–70%, 1x, 컨테이너 밖으로 bleed | 실제 화면이 없으면 성립하지 않는다 |

## 7. direct 가 무브를 쓰는 법

- 브리프 4장 "시그니처 무브"에 레퍼런스 무브를 옮기고 **채택 / 변형 / 버림**을 표시한다. 변형이면 바뀐 수치를 쓰고,
  버림이면 이유(콘텐츠 조건 미충족, 브랜드와 충돌)를 쓴다.
- 무브는 레버에 묶여 있어야 옮길 수 있다. "제품 화면이 오른쪽으로 넘친다"는 실제 제품 화면이 있어야 성립한다. 이런 조건은
  "깨지는 경우"에 적어 두면 direct 가 채택 여부를 판단한다.
- 검증(direct 7단계)에서는 무브마다 반영 / 부분 / 없음을 판정한다. 그래서 무브의 수치는 결과 캡처에서 다시 잴 수 있는 값으로 쓴다.
- 브리프 8장 Don't 는 무브 번호를 인용한다("무브 2 를 깬다 — 섹션 사이 hairline 금지").
